Agent recipes

Workflows that keep AI agents on track

AI agents can write a lot of code fast, and they can break a lot fast too. These recipes are short routines with a prompt you can copy, so the agent plans, changes one thing at a time, and shows its work.

Recipe

Plan first, then build

Use it when: Starting any new feature or project.
Works with: Any coding agent (Cursor, Claude Code, Codex, Copilot agent mode, Replit, Lovable, Bolt)

  1. Paste the prompt and describe what you want.
  2. Read the plan. Cross out anything you don't need.
  3. Reply "Do step 1 only."
  4. Test, then ask for the next step.
Before writing any code, make a plan for: [what you want to build].

Rules:
- Break it into 3 to 7 small steps. Each step must be testable on its own in under 5 minutes.
- For each step, list which files you will create or change.
- Say what I should check after each step to know it works.
- List anything you are unsure about as questions for me.

Do not write code yet. Wait for me to say "go to step 1".

Checkpoint: You have a numbered plan, and the agent stopped and waited instead of writing code.

Recipe

One change at a time, with save points

Use it when: You have something that works and don't want the AI to break it.
Works with: Any coding agent

  1. Save a copy of your working project first (a git commit, or copy the folder).
  2. Ask for one change with the prompt.
  3. Test. If it broke, go back to the save point instead of asking for fix after fix.
My project works right now. Make this one change only: [the change].

Rules:
- Change as few lines as possible. Do not rename, reformat or "clean up" anything else.
- Do not delete any files.
- When you're done, list every file you changed and, for each one, a one-line summary of what changed and why.
- Tell me exactly how to test that the change works and that nothing else broke.

Checkpoint: Only the files you expected changed, and your old features still work.

Recipe

Bug hunt: cause first, fix second

Use it when: Something is broken and you don't know why.
Works with: Any AI assistant

  1. Write down the exact steps that cause the bug.
  2. Copy the full error (browser: F12, then Console).
  3. Use the prompt. Don't accept a fix until the cause makes sense to you.
I have a bug. Help me find the cause before fixing anything.

What I expected: [what should happen]
What actually happens: [what happens]
Steps to make it happen: [1, 2, 3]
Error message (exact): [paste, or "none"]
Relevant code: [paste]

First, list the 3 most likely causes, most likely first, and how I can check each one (for example a console.log to add). Then wait for my results before suggesting a fix.

Checkpoint: You know which line caused it and why, and the fix is small.

Recipe

Explain it before you accept it

Use it when: The agent just made a big change and you're not sure what it did.
Works with: Any coding agent

  1. Run this before you keep any large change.
  2. If the agent can't explain a change simply, ask it to undo that part.
Before I keep your changes, review them like a careful teacher.

1. Summarize what you changed in 5 bullets or fewer, in plain language.
2. List anything you changed that I did NOT ask for.
3. List any risks: things that could break, data that could be lost, or anything that touches passwords, keys or personal information.
4. Give me a 3-step test to check it works.

Be honest if something is uncertain.

Checkpoint: You can explain the change to a friend in two sentences.

Recipe

Ship a static site to GitHub Pages

Use it when: Your project is one or more HTML files and you want a link to share.
Works with: A free GitHub account (GitHub requires users to be 13+, so younger builders need a parent to own the account) and any AI assistant

  1. Create a public repository on GitHub and upload your index.html.
  2. In the repository: Settings, then Pages, then deploy from the main branch.
  3. Wait a minute, then open the link GitHub shows you.
  4. Use the prompt to check your files before you publish.
I'm about to publish this project as a public website on GitHub Pages. Check it first:

1. Is there anything personal in the files (my full name, school, address, email, passwords, API keys)? List exact lines.
2. Will it work as a static site with no server? (No Node, no database.)
3. Are all file paths relative and correctly capitalized? (GitHub Pages is case-sensitive.)
4. Is the main file named index.html?

Here are my files: [paste or list them]

Checkpoint: Your page opens at your username.github.io/repository-name link on your phone and a computer.

Recipe

Research digest with real sources

Use it when: You want to catch up on a topic without trusting made-up facts.
Works with: An assistant with web search (for example Perplexity, ChatGPT or Gemini with search on)

  1. Use the prompt with a topic and a date range.
  2. Open at least two of the links yourself.
  3. Delete anything the sources don't back up.
Find the most important news about [topic] from [start date] to [end date].

For each item give: a one-sentence summary, the date, and a link to the original source (not a summary site). Only include items you found a source for. If you are not sure about something, say "unverified" instead of guessing. Give at most 7 items, most important first.

Checkpoint: Every item has a working link, and the link actually says what the summary says.

Recipe

Playtest checklist for your game

Use it when: Your game works and you want to find bugs before friends do.
Works with: Any AI assistant

  1. Paste your game code with the prompt.
  2. Go through the checklist yourself, ticking each line.
  3. Fix the worst bug first, one at a time (use the checkpoint recipe).
Here is my browser game: [paste code or describe it].

Write a playtest checklist I can do in 10 minutes. Include:
- 5 normal things a player does (and what should happen)
- 5 weird things a player might try (mashing keys, resizing the window, playing on a phone, pausing the tab, getting a huge score)
- 3 places in my code where a bug is most likely, and why

Format it as a checklist with [ ] boxes.

Checkpoint: You ran every line of the checklist and wrote down what failed.

Safety rules for every recipe

  • Never paste passwords, API keys or personal information (yours or anyone else's) into an AI tool.
  • Keep a save point (git commit or a copy of the folder) before letting an agent edit files.
  • Read what the agent wants to run before you approve commands.
  • Check each tool's age rules. Under 13? Use tools with a parent.
