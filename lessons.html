Vibe coding lessons

Ten short beginner lessons. Each ends with a mini project.

Ready for a full build? Try a project guide: exact prompts, checkpoints and finished, tested code.

Lesson 1

What is vibe coding?

Vibe coding means describing what you want in plain language and letting an AI write the code, then testing and steering it. You stay in charge of the idea and the checking.

  • Pick one tiny goal, not a whole app.
  • Describe it clearly: what it does, who uses it, what it looks like.
  • Run the result, then ask for one change at a time.
  • Save working versions before big changes.
Mini project: a personal landing page. Ask an AI for a one-page HTML site with your name, a short bio and three links.
Lesson 2

Prompting for code

Good prompts give context, constraints and a definition of done. Specific beats long.

  • State the language and tools (e.g. plain HTML, CSS, JS).
  • List what must work and what to avoid.
  • Paste exact errors when something breaks.
  • Ask the AI to explain its changes.
Mini project: a to-do list. Build an add, check off and delete list that saves to the browser's localStorage. Full step-by-step guide with tested code →
Lesson 3

Build a tiny game

Games are a fun way to practice because feedback is instant. Start with one mechanic.

  • Choose one mechanic, like clicking targets or dodging.
  • Get a basic loop running first.
  • Add score, then difficulty, then polish.
  • Test on both desktop and phone.
Mini project: a click-the-target game with a score and a 30-second timer. Want a bigger build? Build a dodge game step by step →
Lesson 4

Debugging with AI

Bugs are normal. The skill is giving the AI enough information to help you find the cause instead of guessing.

  • Reproduce the bug and write down the exact steps.
  • Copy the full error message and the code around it.
  • Ask for the likely cause before asking for a fix.
  • Change one thing, retest, and repeat.
Mini project: break your to-do list on purpose (for example, remove a bracket), then use an AI to find and explain the fix.
Lesson 5

Working with files and structure

Real projects use several files. A little organization keeps the AI, and you, from getting lost.

  • Split code into index.html, style.css and script.js.
  • Tell the AI which file each change belongs in.
  • Keep file names short and descriptive.
  • Ask the AI to summarize how the files connect.
Mini project: split your landing page into three files and add a simple second page with a link between them.
Lesson 6

Using APIs, safely

APIs let your project fetch live data like jokes, weather or game stats. Keep secrets out of your page code.

  • Pick a free public API with no key to start.
  • Ask the AI to fetch the data and show it on the page.
  • Handle errors, such as a failed request, with a friendly message.
  • Never paste private keys into front-end code or share them in chats.
Mini project: a joke-of-the-day page that fetches from a public API and has a New joke button.
Lesson 7

Making it look good

A clear layout beats fancy effects. Describe the style in words and let the AI apply it consistently.

  • Pick 2 colors and one font, then stick to them.
  • Ask for generous spacing and a clear heading order.
  • Check your page on a phone-sized screen.
  • Request small tweaks instead of full redesigns.
Mini project: restyle your landing page in a clean, minimal look and make it work well on mobile.
Lesson 8

Share your project

A project is more fun when others can try it. Static sites are the easiest to put online.

  • Test every button and link one last time.
  • Write a short README saying what it does.
  • Choose a static host such as GitHub Pages or Netlify.
  • Ask the AI to walk you through uploading, and read each step before you confirm.
Mini project: publish your best project from these lessons and share the link with a friend for feedback.
Lesson 9

Working safely with AI agents

Agents can read files, run commands and act inside your accounts. The more they can reach, the more one mistake can cost, so give them only what a task needs and keep the risky steps for yourself.

  • Start an agent in one project folder, not your whole computer or your main accounts.
  • Keep API keys in a .env file listed in .gitignore, never in page code, prompts or screenshots.
  • Give each tool its own key, so one leaked key is easy to find and replace.
  • Skip "always allow" and require your approval for paying, sending, deleting or sharing personal info.
  • Review what changed, for example with git diff, before you keep an agent's work.
Mini project: run the Find leaked secrets prompt on one of your projects, move any keys it finds into a .env file, add .env to .gitignore, and replace any key that was ever committed or shared. Open the prompt library →
Lesson 10

Handing off work to a background agent

Some agents can now keep working while you do something else. That is useful, but you will not be watching each step, so the brief and the check at the end matter more than ever.

  • Write a short brief: the goal, the folder or files it may touch, and what "done" looks like.
  • Ask it to stop and wait for you before anything it cannot undo, like deploying, paying or deleting.
  • Ask for a written summary at the end: what it changed, what it tested and what it is unsure about.
  • Check the result yourself before you keep it, for example with git diff and by running the app.
Mini project: give an agent one small task on a practice project, such as adding a dark mode toggle, using the Agent task brief prompt. When it finishes, compare its summary with the real changes and note anything it missed. Open the prompt library →
